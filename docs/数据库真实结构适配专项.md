# 数据库真实结构适配专项

## 目标

- 系统梳理当前 Koa2 Backoffice 对真实 MySQL 结构的字段假设
- 优先覆盖以下表：
  - `tbl_video`
  - `tbl_tv_show`
  - `tbl_shorts`
  - `tbl_tv_show_video`
  - `tbl_shorts_episode`
  - `tbl_rent_transaction`
  - `tbl_withdrawal_request`
  - `tbl_type`
  - `tbl_channel`
- 减少“页面可进但查询报字段不存在”的问题
- 将共享类型定义从“理想模型”调整为“真实库模型 + 显式兼容层”

## 当前结论总览

### 已基本收口

- `tbl_video`
- `tbl_tv_show`
- `tbl_shorts`
- `tbl_tv_show_video`
- `tbl_shorts_episode`
- `tbl_rent_transaction`
- `tbl_withdrawal_request`
- `tbl_type`
- `tbl_channel`

### 仍有专项风险

- `Shorts` 与 `ShortsEpisode` 曾长期复用 `TV Show` 理想类型
- admin 内容管理线当前只做到最小可用：列表 + 状态切换/入口页
- 部分页面仍依赖兼容字段而非真实字段语义

## 3. `tbl_shorts`

### 当前真实结构适配情况

`tbl_shorts` 是当前最典型的“理想模型误复用”案例，已经完成以下关键修正：

- 创建时不再写入不存在字段：
  - `channel_id`
  - `landscape`
  - `release_date`
  - `is_rent`
  - `price`
  - `rent_day`
  - `avg_rating`
  - `total_review`
- 更新时不再更新不存在字段
- 发布时不再更新不存在的 `channel_id`
- 数据回填时不再读取不存在字段：
  - `release_date`
  - `landscape`

### 本次专项新增修正

已把以下共享类型从 `TV Show` alias 改为显式 `Shorts` 类型：

- `ProducerShortsItem`
- `ProducerShortsDetail`
- `ProducerShortsEpisodeItem`
- `ProducerShortsEpisodeDetail`

虽然字段集合目前仍保持兼容形态，但**类型定义不再通过 alias 隐式继承 TV Show 语义**。

### 当前兼容层说明

当前 `Shorts` 类型中仍保留以下兼容字段：

- `channel_id`
- `landscape`
- `release_date`
- `is_rent`
- `price`
- `rent_day`

这些字段在 repository 层已被显式处理为兼容输出或固定默认值，而不是继续直接写库。

### 风险等级

- 低

### 风险原因

- 当前字段与代码假设整体一致
- 主要剩余风险已经从“字段不存在”转为“Laravel 语义是否完全一致”

### 下一步建议

- 后续重点转向：
  - Laravel 原 episode 校验规则
  - 删除级联与发布流转语义

## 共享类型与兼容层建议

### 已处理

- `Shorts` / `ShortsEpisode` 不再直接 alias 到 `TV Show` / `TV ShowEpisode`

### 仍建议继续处理

- 把 `AdminVideoItem` / `AdminTvShowItem` / `AdminShortsItem` 与 producer 侧类型彻底分离
- 视图层逐步减少对兼容字段的依赖
- 把“页面展示需要的字段”与“真实表写入字段”分层

建议分三层：

- `RawRow`：真实数据库返回字段
- `DomainModel`：服务层业务模型
- `ViewModel`：页面渲染所需字段

## 当前阶段性结论

当前 Backoffice 的数据库真实结构适配已经从“频繁字段不存在报错”推进到“核心主链可用 + 少数模块仍靠兼容层”。

现阶段最需要继续收口的不是 `tbl_video` / `tbl_tv_show` / `tbl_shorts` 主表本身，而是：

- `Shorts` 视图层继续去 `TV Show` 化
- admin 深层 CRUD / 发布 / 排序能力
- 与 Laravel 原语义继续对照补齐
