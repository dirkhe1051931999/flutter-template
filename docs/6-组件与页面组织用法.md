# 组件与页面组织用法

## 一、当前组织方式

你项目整体是「页面组合组件」的方式：

- `pages/`：页面级容器，负责组合与流程
- `components/`：可复用 UI 单元，负责局部交互

## 二、典型例子：TodoList

### 页面层

文件：`lib/pages/todolist/index.dart`

职责：

- 管理 `TextEditingController`
- 组合 `ListWidget / InputWidget / AddWidget / ClearWidget`

这非常像前端中的「容器组件」模式。

### 组件层

文件：`lib/components/todolist_detail/*.dart`

- `input.dart`：输入框
- `add.dart`：添加按钮（含 dispatch）
- `clear.dart`：清空按钮（含 dispatch）
- `list.dart`：列表展示与删除交互

## 三、页面包装组件 `PageScaffold`

文件：`lib/layouts/app_wrap/index.dart`

作用：

- 统一二级页面的 `Scaffold + AppBar + 返回按钮`
- 在路由 handler 中复用

示例（`handler.dart` 中）

```dart
return const PageScaffold(
  title: 'Request',
  widget: RequestPage(),
);
```

## 四、如何新增一个业务页面（推荐步骤）

1. 在 `pages/` 新建页面，如 `pages/settings/index.dart`
2. 如需拆分，新增 `components/settings_detail/*.dart`
3. 在 `router/handler.dart` 里包一层 `PageScaffold`
4. 在 `router/routes.dart` 注册路径
5. 在首页加入口按钮

## 五、组件设计建议（结合你当前项目）

- 页面组件做「数据组织和流程控制」
- 小组件做「输入、展示、单一按钮行为」
- 组件内部尽量避免关心路由初始化、网络实例初始化
- 如果某块逻辑复用超过 2 次，就提升到 `components/`

## 六、从前端思维迁移到 Flutter 的对照

- Vue 页面（View）≈ Flutter `pages/*`
- Vue 子组件 ≈ Flutter `components/*`
- `props` ≈ 构造参数
- `emit` ≈ 回调函数参数
- 全局状态（Pinia/Vuex）≈ Redux Store

## 七、快速自检清单

新增页面前先问自己：

- 这是页面职责还是组件职责？
- 状态是局部 `setState` 还是全局 Redux？
- 是否需要复用 `PageScaffold` 保持一致性？
- 是否已经在路由集中注册？
