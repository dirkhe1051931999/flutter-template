# 启动流程与目录结构

## 一、启动流程（必须先理解）

### 1) 入口：`main.dart`

`main()` 做两件事：

- 调用 `createAppBootstrap()` 创建 router/store
- `runApp(Layout(...))` 启动应用

### 2) 引导：`bootstrap.dart`

`createAppBootstrap()` 负责：

- `createAppRouter()`：创建 FluroRouter 并注册路由
- `createAppStore()`：创建 Redux Store
- `configureEasyLoading()`：配置 loading UI

你可以把它理解为：应用启动期的集中初始化层。

### 3) 应用外壳：`layouts/index.dart`

`Layout` 负责：

- `ScreenUtilInit` 响应式适配
- `StoreProvider` 注入 Redux Store
- `MaterialApp` 配置主题与路由生成器

关键点：

- 路由入口：`onGenerateRoute: router.generator`
- 全局状态注入：`StoreProvider(store: store, child: MaterialApp(...))`

## 二、目录结构（按职责理解）

```text
lib/
├── main.dart
├── bootstrap.dart
├── app.config.dart
├── layouts/
├── router/
├── store/
├── pages/
├── components/
├── api/
├── model/
└── utils/
```

## 三、每个目录是干什么的

### `layouts/`

- 应用壳层（主题、注入、MaterialApp）
- 示例：`lib/layouts/index.dart`
- 子目录 `app_wrap/` 提供页面容器 `PageScaffold`

### `router/`

- 路由路径常量、handler、全局 router 单例
- 核心文件：
  - `lib/router/routes.dart`
  - `lib/router/handler.dart`
  - `lib/router/config.dart`

### `store/`

- Redux 状态、action、reducer
- 核心文件：
  - `lib/store/index.dart`（`AppState` + 根 reducer）
  - `lib/store/action.dart`（`AppAction` 基类）
  - `lib/store/todolist/*`
  - `lib/store/user/*`

### `api/`

- 业务接口层，调用统一 `httpClient`
- 示例：`lib/api/banner.dart`

### `model/`

- 数据结构与 json 映射
- 示例：`lib/model/banner/index.dart`

### `pages/`

- 页面级组合与业务流程
- 示例：
  - `lib/pages/home/index.dart`
  - `lib/pages/todolist/index.dart`
  - `lib/pages/request/index.dart`

### `components/`

- 可复用 UI / 页面子组件
- 示例：`lib/components/todolist_detail/*.dart`

### `utils/`

- 基础设施工具
- 示例：`lib/utils/request.dart`（Dio 封装）

## 四、你可以先记住的三句话

- 入口只负责启动，业务逻辑不要放 `main.dart`
- 页面负责组合，接口请求放 `api/`，网络实例放 `utils/request.dart`
- 全局状态统一经 `store.dispatch(AppAction)` 更新
